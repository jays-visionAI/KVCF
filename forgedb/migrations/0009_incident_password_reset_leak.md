# 2026-10-05 · 어드민 비밀번호 알림 메일 사건 (원인 확정 · 조치 완료)

## 증상

새벽 2시경 어드민 계정 관련 **"비밀번호가 변경되었습니다" 알림 메일 2통** 도착.
사용자는 비밀번호를 변경한 적이 없다고 진술.

## 조사에서 확정된 사실

1. **앱 코드에 비밀번호 변경 경로는 존재하지 않는다.**
   `updateUser` / `resetPasswordForEmail` / `verifyOtp` / `recovery` 전 프로젝트 grep 결과 0건.

2. **원격에 3개의 폐기 함수가 살아 있었고, 삭제는 실패했다.**
   - 로컬 삭제: v0.12 커밋 `93954fe` (파일이 사라졌을 뿐)
   - 원격 삭제 시도: `DELETE /functions/v1/<name>` → **HTTP 405** (ForgeDB 가 DELETE 미지원)
   - 따라서 "로컬에서 파일을 지웠다"는 사실이 "원에서도 사라졌다"는 뜻이 아니었다.
     이 갭이 사고의 직접 원인이다.

3. **살아 있던 함수가 하던 일**
   - `reset-admin-password` → `jays@blueforge.space` 계정 **영구 삭제 후 동일 이메일로 재생성**,
     기본 비밀번호를 코드에 하드코딩해 주입. 인증은 `service_role` 키 단독.
   - `admin-reset-jays-password` → Postgres 직접 연결해 비밀번호 해시 덮어쓰기.
     (확인 결과 이 DB 스키마엔 해당 컬럼이 없어 실제로는 동작 불가였음)
   - `issue-admin-magic-link` → 하드코딩 수신자 + 만료된 redirect URL. 재사용 불가 상태.

4. **비밀번호 변경 이력은 이 시스템에 기록되지 않는다.**
   `auth.users` 에는 해시 컬럼이 없고(8개 컬럼), 관리자 API 응답에도
   `password_changed_at` 계열 필드가 없다. 감사 로그 테이블도 없다.
   → "언제/누가/무엇으로 바꿨다"는 사후 확인 자체가 불가능하다. 이때부터
   "확인" 대신 "재설정"이 유일한 정답이었다.

## 결론 — 왜 메일이 왔나

누가 직접 비밀번호를 바꾼 게 아니다. 살아 있던 `reset-admin-password` 가
계정을 삭제·재생성하면서 ForgeDB 인증 파이프라인이 **알림 메일을 자동 발송**한 것이다.
ForgeDB 는 이 프로젝트에서 사용자 이메일을 인증 메일 발신자로 그대로 쓰기 때문에
발신자가 "ForgeDB" 로 찍혔다.

## 남은 작업 (콘솔에서만 가능)

- **service_role 키 회전** — 이 키는 과거 로그와 폐기 함수 안에 노출된 이력이 있다.
  이번 조치로 계정 파괴 capability 는 0이 됐지만, 키 자체는 아직 유효하다.
  회전은 ForgeDB 콘솔에서만 가능하며 **콘솔 로그인 + 키 재생성**이 필요해
  자동화하지 않았다. 회전 후 `.env` 의 `FORGEDB_SERVICE_ROLE_KEY` 를 갱신해야 한다.
- **3개 폐기 함수의 완전 삭제** — 스텁으로 무력화는 끝났지만 엔드포인트 자체는
  남는다. 콘솔 Functions 탭에서 삭제하면 되며, 삭제 전까지는 무해하다.

## 재발 방지 원칙

1. **Edge Function 삭제는 "로컬 파일 삭제"가 아니다.** 반드시 원격 응답으로
   실제를 확인한다(`GET /functions/v1/<name>` → 405 = 살아 있음).
2. **비밀번호를 다루는 함수를 만들지 않는다.** 인증은 ForgeDB 콘솔과
   `auth-magic-link` 만 쓴다.
3. **하드코딩된 기본 비밀번호를 코드에 남기지 않는다.** 응급 복구 코드를 만들더라도
   같은 방식으로 곧바로 무력화한다.
